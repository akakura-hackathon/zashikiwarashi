## 1. 撮影の目的と審査基準対応

本デモ動画は、Google Cloud Japan AI Hackathon Vol.5 の **3つの審査基準** を5分間で審査員に強く印象付けることを目的とします。

| タイムライン | 実演内容 | アピールする審査基準 |
|---|---|---|
| **0:00〜0:45** (45秒) | 課題提起とコンセプト説明（平時の手入力ゼロ・人物プロファイリング禁止） | **① 課題の新規性と有効性** |
| **0:45〜2:00** (75秒) | 災害発令 ＆ **Building Coordinator Agent** による空間近接トリアージ | **② 自律性・エージェントらしさ** |
| **2:00〜3:15** (75秒) | 住民スマートフォン体験 ＆ **段階的開示（Progressive Disclosure）** | **② 自律性** ＆ **③ 実装品質** |
| **3:15〜4:15** (60秒) | **Google Cloud Model Armor** 攻撃遮断 ＆ Policy Engine ガバナンス | **③ 実装品質とセキュリティ** |
| **4:15〜5:00** (45秒) | 全体アーキテクチャ（Vertex AI Agent Runtime 独立マルチ構成）と結び | **③ 拡張性と完成度** |

## 1.5 審査員の操作手順（アプリ内デモガイド。#63）

審査員は本番 URL で1人で操作する。検証画面（左パネル）上部の「審査デモガイド」が、アプリの状態から進み具合を判定し、次の操作・見どころ・必要なペルソナ切り替えボタンを表示する（`frontend/components/DemoGuide.tsx`）。

| # | 画面 | 操作 | 見どころ |
|---|---|---|---|
| 1 | どちらでも | 「地震」を選び「震度5強 地震発生」 | 管理人のワンタップで50戸へ安否確認を一斉配信 |
| 2 | 住民301 | 安否確認で「無事」 | 平時の手入力ゼロ。災害時だけこの1問に答える |
| 3 | どちらでも | 「1回目のトリアージをする」 | Building Agent が同じ階で一番近い「無事」の住民を確認役に選ぶ。「隣室確認の状況」に誰が誰を確認するかが出る |
| 4 | 住民301 | 依頼で「協力する」→「応答がなかった」 | 承認前は部屋番号を伏せ、承認した瞬間だけ開示（段階的開示・Human-in-the-Loop） |
| 5 | 管理人 | 「隣室確認の状況」と最優先アラートを見る | 確認先が「要対応・応答なし」の先頭に出る。管理人は50戸ではなく数戸だけに向かえばよい |
| 任意 | 管理人 | 「Agentガバナンス検証」タブ | Model Armor が攻撃を遮断する |

- 301号室の確認先は、Gemini の割り当てによって302号室以外になる場合がある。ガイドは実際のタスクから確認先を表示する。
- 301号室に依頼が届かなかった・「被害あり」と回答した・辞退した場合は、ガイドの「最初からやり直す」（地震を発令し直す。前の緊急事態は API が閉じる）で戻る。
- 本番では審査員全員が同じ建物データ（`bld-01`）を共有するため、同時に操作すると表示が混ざる。ガイドに注意書きを出している。

## 2. 撮影前の準備・チェックリスト

1. **画面表示の設定**:
   - ブラウザで `https://zashikiwarashi.web.app`（または `http://localhost:3000`）を開く。
   - ウィンドウ幅を 1400px 以上に広げ、**「左: 防災センター コックピット」** と **「右: スマートフォン実機フレーム」** が綺麗に 1 画面に収まるようにする（Studio Architecture）。
2. **デモセッションの有効化**:
   - 右側の住民スマートフォンエリアにある **「🚀 クイックデモセッションで開始（審査用）」** をクリック。
   - 住民ペルソナが「住民 I（301号室）」として右側スマホ画面がアクティブになっていることを確認。
3. **データリセット（初期状態の確認）**:
   - 災害シミュレーション表示が「○ 平常時」、安否状況が平常待機中であることを確認。

## 3. タイムテーブル ＆ 実演絵コンテ

```
===================================================================================
【0:00 - 0:45】 導入: 課題提起とソリューションの新規性
===================================================================================
画面: 
  ・Studio 全体画面（平常時）。
ナレーション / スピーチ:
  「マンションの大規模災害時、エレベーター全基停止による『垂直孤立』が深刻な社会問題となっています。
   公的救助が届くまでには時間がかかり、棟内での助け合い（共助）が不可欠です。
   しかし、平時からボランティア登録を募るとプライバシーの懸念や人間関係の負担から誰も登録しません。
   そこで開発したのが『Zashikiwarashi』です。
   『平時の手入力ゼロ』『人物プロファイリング禁止』を徹底し、災害時だけ自律的に立ち上がる Multi-Agent 防災システムです。」
テロップ:
  ・都市型タワマンの「垂直孤立」問題を解決
  ・平時の手入力ゼロ × 人物プロファイリング禁止
```

```
===================================================================================
【0:45 - 2:00】 シナリオ実演①: 災害発令 ＆ Building Coordinator Agent の空間近接トリアージ
===================================================================================
操作手順:
  1. 左パネルで「🚨 震度5強 地震発生」ボタンをクリック。
  2. 左下ログに「[API-01] 震度5強 地震発生！ 緊急モード発令」と全50戸への一斉配信が表示される。
  3. 中央の安否集計（FloorMap）がリアルタイム更新されるのを見せる。
  4. 左パネルの黒いボタン「トリアージ開始」をクリック。
  5. 3〜5秒待ち、推論結果ログが表示される。
ナレーション / スピーチ:
  「地震が発生しました。管理人がワンタップで緊急モードを発令すると、棟内50戸へ一斉に安否確認が配信されます。
   ここで『トリアージ開始』を押すと、Vertex AI Reasoning Engines 上で稼働する Building Coordinator Agent が起動します。
   Gemini 2.5 Flash が棟内の階層・エレベーター停止状況・近接距離を自律推論し、
   『階段を使わず同フロアで隣室を確認できる住民I（301号室）』を見つけ出し、未応答の高齢者世帯（302号室）の安否確認タスクを自動立案しました。」
テロップ:
  ・Building Coordinator Agent (Vertex AI Reasoning Engines 独立稼働)
  ・Gemini 2.5 Flash による空間近接性トリアージ（階段移動を最小化）
```

```
===================================================================================
【2:00 - 3:15】 シナリオ実演②: 住民スマートフォン体験 ＆ 段階的開示（Progressive Disclosure）
===================================================================================
操作手順:
  1. 右側のスマホ画面にカメラ/視点を寄せる（住民I・301号室）。
  2. スマホ上に届いたタスク「隣室の安否確認のお願い（3階 未応答住戸）」を確認。
  3. この時点では『部屋番号が伏せられている（抽象トークン）』ことを強調して見せる。
  4. スマホ画面の「協力する（承認）」ボタンを1タップ。
  5. 承認完了と同時に、画面上に「302号室」と相手の正確な部屋番号が開示される！
  6. インターホンを鳴らした想定で「応答がなかった」をタップして報告する。
  7. 左パネルで管理人に切り替え、「隣室確認の状況」の要対応の先頭と最優先アラートに確認先の住戸が出ることを見せる。
ナレーション / スピーチ:
  「右側の住民スマートフォンをご覧ください。
   タスクが届いていますが、相手の部屋番号は『3階の未応答住戸』とだけ表示され、まだ伏せられています。
   これが私たちの設計原則である『段階的開示（Progressive Disclosure）』です。
   住民が内容を確認し、自分の意思で『協力する』とワンタップ承認した瞬間にだけ、
   コード（Policy Engine）が安全に部屋番号『302号室』を開示します。
   AIが勝手に個人情報をばら撒くことは一切ありません。」
テロップ:
  ・段階的開示（Progressive Disclosure）: 本人承認前は部屋番号を完全秘匿
  ・Human-in-the-Loop: 実世界のアクション確定は必ず本人の承認を通す
```

## 4. 撮影トラブルシューティング

- **Q. 本番環境（`zashikiwarashi.web.app`）でログインダイアログが出る場合:**
  - 右側スマートフォンの「🚀 クイックデモセッションで開始（審査用）」ボタンを必ず先に押してください。
- **Q. 前のテストデータが残っている場合:**
  - ページをリロードすると最新の緊急事態セッションが自動復元されます。新しい災害でテストしたい場合は、左パネルで別の災害種別（⚡ 停電、🔥 火災、🌊 洪水）を選択して発令できます。
- **Q. 動画の書き出し形式:**
  - 解像度: 1920x1080 (Full HD) 推奨。
  - 音声: マイク音声をクリアに録音、重要ポイントにテロップを配置。
