| 項目 | 内容 |
| --- | --- |
| 対象 | 「ZASHIKI 画面モック（SC-1〜4）」の全56画面＋遷移表・通知一覧・遷移図 |
| 目的 | モックの見た目・文言・挙動を、**そのまま本番画面として実装できる**粒度で固定する |
| 作成方法 | モックのソース（インライン CSS・文言・遷移表）から値を機械的に抽出して記載。推測・提案は【提案】、モックに無い／未決は【未決】と明記 |

## 1. デザイン原則（モックから読み取れる一貫した方針）

1. **白地・黒文字・細い罫線。** 色は「意味があるときだけ」使う（緑＝進める／赤＝危険・119／黄土＝進行中・注意）。装飾に色を使わない。
2. **1画面1問い、選択肢は最大2つ。** 緊急時に迷わせない。ロック画面通知も2ボタンまで。
3. **全画面に 119。** 右上に常に赤い「119」。文言でも「119番の代わりではありません」を繰り返す。
4. **個人情報は最小・一時開示。** 部屋番号は承認後だけ表示し、確認を担当した本人には完了画面でも表示する。ロック画面には出さない。何を使い何を見せたかを必ず利用者に見せる。
5. **断っても不利益なし。** 「今は無理（理由は不要）」を対等なボタンとして置く。評価・ランキングは出さない。
6. **重大操作は誤操作防止。** 発令・終了は「長押し 2秒」。
7. **読み上げ・声入力（設計済み拡張 EXT-09）。** 本番拡張候補。MVPでは視認性・1画面1問い・タップ領域のアクセシビリティを優先し、音声入出力はデモ対象外（非表示）。
8. **タップ領域は 44px 以上**（ボタン 44〜56、行 52〜54）。

## 4. 画面インベントリ

### 4.1 ID体系

- 住民：`R01〜R10`（SC-3）／`S1_A*` `S1_B*` `S1_C*`（SC-1）／`S2_E*` `S2_F*`（SC-2）／`S4_L*` `S4_M*`（SC-4）
- 管理人：`A01〜A06`（SC-3 共通）／`S1_M*` `S2_M*` `S4_M_*`
- 平常時：住民 `P_R1〜3`、管理人 `P_M1〜5`（`P_M1b` は通知異常時の派生）
- 【提案】本番のルートは `/{role}/{scenario}/{screen}`（例 `/resident/quake/safety-check`）。画面ID はモックと同じものを定数として残し、設計書・テスト・遷移図と1対1で追えるようにする。

### 4.2 「同じ型の画面」の共通化（実装は1コンポーネント）

モックの遷移表は、複数シナリオで同型の画面を明記している。コンポーネント化の単位とする。

| 型 | 使用画面 |
| --- | --- |
| **待機画面**（回答済み・状況表示） | R03、S1 各「待機」遷移先 |
| **完了・開示の終了**（ありがとう＋使われた情報／開示した情報） | R08、S1_A4/B3/C4、S2_E3/F4、S4_L3/M3 |
| **同行中** | S2_F3、S4（M② → M③） |
| **ロック画面通知（2択）** | R01、R04、S1_A1/B1/C1、S2_E1、S4_L1 |
| **発令画面（災害種別＋指示＋送信先＋長押し）** | A01、S1_M1、S2_M1、S4_M_trigger |

## 8. アクセシビリティ要件

- すべてのアイコンボタンに `aria-label`（戻る／メニュー）。装飾 SVG は `aria-hidden`。
- 現在タブに `aria-current="page"`、トグルに `aria-pressed`。
- タップ領域 ≥ 44px。本文 ≥ 14px、補足でも ≥ 12.5px を維持。【提案】OS の文字拡大に追従（`rem` 化し、固定高さのボタンは `min-height` に）。
- 色だけで状態を伝えない：必ず文言（最優先／被害あり／担当なし）を併記（モックはこの方針）。
- 「画面を読み上げる」（C1）と「声で伝える」（C7）は設計済み拡張（EXT-09）とし、MVPデモでは除外（非表示）。本番拡張候補とする。
- フォーカスリング：`0 0 0 3px #FFF, 0 0 0 5px #C23B2E`（モックの定義）。
- ロック画面通知は OS の通知アクション（ロック解除不要）で実装可能な範囲を確認する【要検証】。

## 9. 本番化の実装指針【提案】

モックは 390×844 固定・インライン style のため、そのまま本番に載せると次が問題になる。見た目を変えずに直す方針：

1. **トークン化**：第2章の値を CSS 変数（または Tailwind／デザイントークン）へ。インライン style は使わない。
2. **可変幅**：390px 固定をやめ、`max-width: 480px` 中央寄せ・横 padding 24 を維持。高さは `100dvh`＋`env(safe-area-inset-*)`。下部アクション領域は `margin-top:auto` の縦 flex を踏襲。
3. **コンポーネント化**：第3章 C1〜C27 を部品に。第4.2節の「同じ型」を1コンポーネント＋props（災害種別・文言・ロール）で共通化。
4. **フォント**：Zen Kaku Gothic New / IBM Plex Mono を使用ウェイトのみ配信。【提案】自前配信＋`font-display:swap`。
5. **リアルタイム項目**：残り時間・「発令から」・回答数・FloorMap・Timeline は購読（push/SSE 等）で更新。【未決】更新方式。
6. **状態ごとの見た目**：モックは「正常な1状態」のみ。ローディング、通信断、送信失敗、期限切れ、二重タップは**デザイン未作成**（第10章）。
7. **テスト**：画面ID単位でビジュアル回帰（モックの各画面をゴールデンに）。

### FN-01 / FN-06 / FN-08 実装補足（2026-10-06）

- 安否回答の目安は Issue.created_at から2分。毎秒、絶対時刻との差分で更新し、0:00で止める。目安経過後も回答可能で、トリアージは管理人が開始する。画面・住民切替ではリセットしない。

### FN-02 / FN-08 再回答・ペルソナ切替の補足

### FN-08 被害回答後の案内（2026-10-10）

- OPEN・状態未取得では「被害状況を受け付けました。管理人による確認をお待ちください」と表示し、救援フローを表示しない。
