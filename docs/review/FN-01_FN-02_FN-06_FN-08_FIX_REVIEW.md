## 今回の範囲外で見つかった修正候補

1. **FN-06: 協力依頼の「返事の期限」は0:45の固定表示。** 安否回答の目安とは別のタイマー。TaskEvent.expires_at と期限切れ・再打診の仕様を画面まで接続する必要がある。
2. **FN-09: 監査ログのAPI型と画面型が不一致。** APIは audit_event_id / action / occurred_at を返すが、画面は audit_id / event_name / created_at 等を参照している。
3. **FN-08: 外出集計の型が不一致。** frontendは安否状態 OUTSIDE_BUILDING を想定するが、backendでは在館状態 PresenceState の値。外出の可能性を表示する場合は在館コンテキストとの結合が必要。
4. **FN-02: デモ用認可と本番認可の分離。** 今回の合意によりペルソナ切替を維持。現行の業務APIはログイン後のデモヘッダーによる権限・住民切替を許容する一方、/me はカスタムクレームを要求する。実運用時は認証方式を統一し、本人以外の操作を禁止する必要がある。カスタムクレーム付きアカウントのデモ切替不一致は、後続の `FN-02_FN-08_RESIDENT_FLOW_FIX.md` の対応で修正済み。
5. **FN-01 / FN-08: 別端末・再読み込み時の災害再発見。** Studioの emergencyId / issueId はメモリ上のみ。5秒同期はそのStudioが把握しているIssueを対象とし、別端末で新たに発令された災害の検出・リロード後の復元には別途取得経路が必要。
6. **依存関係:** npm ci の監査で既存依存に12件（high 11 / moderate 1）を検出。今回ロックファイルは変更していない。影響確認・更新は別途必要。
